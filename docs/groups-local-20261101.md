# 群聊本机验证与兼容说明

本轮沿用现有顺序、自然随机、人工邀请执行机制，补充真实 VCPToolBox、Electron 与 PWA 的接线证据。
群配置和成员提示词仍由桌面原生配置管理器读取、投影并发布为既有执行快照；不新增群注册表、协议、状态格式或迁移。
模型、群组、成员、话题和工具效果全部为本机合成数据，不调用付费模型。

## 验证入口

```sh
python3 tools/dev-environment/verify_full_runtime.py \
  --package .local/release-assembly/groups-accepted \
  --cases group-sequential,group-invite,group-nature,group-recovery,group-effect,install
```

群聊使用独立验证配置：五个群聊话题加三个 Agent 话题，总数仍为8，没有放宽产品选择上限。
因此该组场景与原有14项完整应用场景分别运行，复用固定端口；不得在同一次调用混入旧 Agent/附件场景。
生成的新成员配置不复制真实聊天、提示词、凭据或运行记录。
工具正常停止固定开发实例，完成后恢复；只管理核实属于本套实例的进程。

- group-sequential：桌面和手机都按 Beta→Alpha 的自定义次序；检查模型、温度、输出上限，
  两轮上下文次序，双端所有消息 ID/内容/哈希及重启后无重派发。
- group-invite：发用户消息不自动调用成员，PWA 显式邀请只执行指定成员，原请求重放不新增发言，
  不添加虚假用户消息，拒绝非成员；JEV 保持现有只读范围。
- group-nature：发言计划已经保存、用户消息尚未提交 Journal 时退出实际后端；
  重启时测试预加载禁止再次调用随机选择器，仍按原计划、原步骤身份执行。
- group-recovery：在步骤回复意图保存后和 Journal 接受后各退出一次；
  保留原回复/步骤/配置快照，只执行剩余已知步骤。
- group-effect：合成工具只在测试目录写入并同步一个标记，未保存结算回执时后端退出。
  重启保持未知与群暂停，不重跑；另一群继续。第二浏览器会话不能取消/放弃原任务。
  原会话使用 PWA 确认放弃，保留原因和调用次数，仅新显式请求再执行。
- install：复用整机安装、回退和再安装，额外核对群计划、位置、步骤身份、attempts 和人工处理标记。

故障注入只在测试进程预加载及原有故障钩子内，不添加产品环境变量、公开故障接口或运行时管理 API。
独立模型调用 JSONL 和副作用标记跨重启保留；不能只凭任务终态判断成功。

## 顺序群聊参数补丁

原宿主顺序执行计算了成员 max_tokens，却在组装实际请求时遗漏该字段；原生人工邀请路径已携带它。
候选为 `VCPChat/Groupmodules/groupchat.js` 声明单独兼容补丁，在顺序请求中传入已有解析结果。
不改变模型解析规则、发言计划、流式响应、超时或工具调度。
补丁有精确前后摘要；本机安装器只允许这个新增的明确路径，不覆盖未知修改。
此前启动诊断和 Linux PDF 补丁继续保留，均在 MANIFEST 的 hostPatches 中列明。

## 验收边界

具体通过结果以对应交付记录和 RESULT.json 为准；原模块测试不能替代群聊整机验收。
本轮仅本机 Linux Electron、Chrome 移动视口、模拟模型和合成工具。
JEV/game 不因本轮成为手机可执行模式，真实业务工具、实体手机和 Windows 不在本轮验收范围内。
公开支持的自然随机规则未被测试替代；测试只在恢复阶段禁止重新选择，以检查已接受计划的稳定性。
