## 实现与兼容

相同附件id只在规范化元数据完全一致时共用一份attachmentData；正文中的引用次数、位置、文件id/hash和提取文本均保留。同id不同内容hash、提取文本或帧元数据继续报`INVALID_ATTACHMENT_METADATA`，已有envelope不能通过覆盖正文把冲突藏起来。入站回放按出现次数匹配本地原生记录，防止两个重复引用都取第一个句柄。手机按出现位置渲染，保留全部引用。

Source单操作上限为16MiB，附件元数据总上限为2MiB；附件以外控制字段仍受原768000字节限制，单文件20MiB和格式限制保持。旧选定模式请求仍限1MiB，不能发布扩展表示。没有截断原文、去掉第二次引用、重命名身份、伪造hash、读取当前工作区或新增任务系统。

新增`source-data-v2`读取/发布能力，Source info声明`sourceDataV2`及两个上限。桌面发送前核对Source、设备、空间、服务器声明及该操作实际需要的体积，兼顾正文、独立metadata和消息内envelope；不能因其中一处较小就漏检。服务端在范围/设备授权后独立检查，客户端声明不能代替Source授权。

旧客户端命中重复引用、大元数据或大消息历史页时返回409。覆盖同步Pull、Source基线、手机当前历史、事件及基线；仅有普通删除事件、没有扩展正文时保持兼容。实际Pull删除事件没有携带旧正文/metadata，不能虚构前驱字段强行拦截，也不为此增加查询或存储状态。

没有新增数据库迁移、表/列、主state版本或Source授权规则。shared contracts统一生成两端与PWA实现；execution-decisions和haltedTopics仍排除运行载荷。新数据接受后不声明旧codec直接降版兼容，安装说明和发布范围已标明保留新codec向前恢复；禁止回退数据库、state、游标、Source绑定或授权。
