日期：2026-10-31（America/Adak）。延续独立实验worktree与分支 `experiment/contracts-boundary`；本轮基线 `0c5cf07b7c3c4de16cea44b1d05415f859b4b43d`。主开发副本仍保持 `9dc099b`，没有合并、部署或生产操作。

后续更正：[第三轮逐项验证](critique-validation-20261031.md)撤回了本文将隔离回执直接列为下一轮路线的建议，第4节四项只是该候选方案的设计条件；第5节比较的是整条实现路径，不能把额外耗时归因于纯函数本身。本文保留当时实验事实和判断，后续决策以第三轮证据为准。

## 本轮判断

**支持局部纯决策与有反馈的窄接口；不支持把耐久确认降成普通通知，也不支持静默跳过坏账。**

这次不是仅作目录调整：重启分类和Journal已提交后的状态补丁已抽进纯函数，并实际接回原执行器和SQLite。用真实写入拒绝、独立文件副作用以及子进程退出检验其边界。

## 1. 纯函数能抽取，但应用决定仍需当前事实

`packages/execution-decisions/src/lifecycle.mjs` 只接收行观察、事件、外部传入时间和回执，输出带前置条件的patch。SQLite适配器保留事务与条件UPDATE；先规划再发生状态变化时，旧计划报 `EXECUTION_OBSERVATION_STALE`，不能覆盖新的派发事实。

- 对固定旧Git对象中的SQL执行252组状态／标记组合，与新纯决策＋真实SQLite应用逐行比较，结果一致。
- 10000组固定种子的重启转换验证确定性与重复重启稳定性。未知派发和已开始工具不会被转回queued。
- 实际SQLite中先计划“未派发取消”，再将request_dispatched置为1，旧计划被拒绝。内存重放正确不等于计划仍适用于当前数据库。
- preparing／publishing仍沿原pending_operation、opId和Journal接受事实恢复，不新增事件日志、数据库或schema。群聊及原生AA仍由原路径管理。

纯决策有助于把语义列清楚，**没有证据表明所有执行逻辑都应该移进一个纯内核**。SQL、原生归档和外部结果仍需要各自的可靠提交边界。

## 2. 普通事件通知与可靠钩子不等价

用SQLite真实trigger拒绝写入mobile_native_invocations：现有awaited onToolDispatch失败后，合成副作用文件没有产生，事务回滚，工具派发记录为0。AA接受记录被真实trigger拒绝时，launch continuation同样没有运行；已发生的外层工具调用仍记录为error，未伪造“从未派发”。

对照支路故意改成普通EventEmitter：异步监听器尚未拿到耐久确认，调用方就写出副作用，随后同一SQLite写入才失败。这证明**没有确认合同的异步广播不能替代派发屏障**。若事件机制明确等待接收方成功、允许拒绝并保留恢复查询，它也可以是可靠SPI；接口名称或补丁行数不是判断标准。

## 3. 真实进程退出暴露内存模型无法替代的边界

三个子进程场景均exit78，使用临时SQLite/WAL、匹配原生模块和合成loopback模型HTTP：

|退出点|观察结果|
|---|---|
|回复意图已落盘、Journal尚未发布|重启只补发原操作，保存同一回复，模型计数仍为1|
|Journal已接受、任务元数据尚未收尾|重启幂等读回并完成元数据，不新增Journal，不再次调用模型|
|独立文件副作用已fsync、原生工具结算回执尚未写入|重启保留review_required及原调用身份，阻止同话题自动接力；没有自动重试|

第三个场景的错误恢复对照支路盲目重试，同一副作用文件出现第2次写入。仅有本地started或意图记录不能证明独立外部动作没有发生。解决这类未知结果需要下游幂等、原生结果查询或人工核对，不能只改状态机名称。

这里是实际进程退出与独立文件模拟的外部效果，不是物理断电测试，也不是付费模型或真实业务工具调用。原生AA的已有整链合成回归继续保留。

## 4. 新确认的缺口：毒丸Journal仍会跨话题阻塞

对已接受的一条授权话题记录注入损坏JSON，再写入另一个健康话题：当前真实HTTP pull返回BAD_REQUEST，接收游标保持旧值，后续健康话题也无法推进。**当前行为是失败关闭，没有静默丢数据，但故障隔离不完整。** 注入模拟存储损坏／历史缺陷，不是普通合法提交就能制造该损坏。

故意实现“吞掉解码错误、按扫描位置继续”的对照后，健康话题能前进；但恢复原始坏记录后，客户端也不会再拉到它，诊断却显示已物化到最新水位。这个对照证明跳过会制造永久漏同步，不能当成修复。墓碑又代表明确删除，同样不能用于包装无法验证的事实。

本轮**没有修复毒丸隔离协议**，没有把该反例的测试通过算作功能通过。安全候选需要进一步定义：

1. 可证明seq、归属和原记录摘要的显式隔离回执，保留服务器原始证据；不能跨越未知授权边界。
2. 客户端先耐久保存待核对项，才能推进接收游标；物化／完整性诊断继续显示缺口。
3. 对已接收的隔离seq建立独立补查与修复流程，不能依赖回拨全局游标或重新发送未知工作。
4. 旧客户端必须明确拒绝不认识的隔离协议，不能静默忽略新字段。

这些是后续验证的设计条件，不是已实现接口或新的生产授权。
