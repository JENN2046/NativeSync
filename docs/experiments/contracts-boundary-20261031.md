# 共享契约与薄适配：独立副本验证

日期：2026-10-31（America/Adak）。实验基线 `9dc099b6007e018a9743d72048d5e6fbb43b94e7`，原tree `82bdf4c2e6201da032294a236f66e756bf8a4f07`。实验分支 `experiment/contracts-boundary`，位于单独managed worktree；主开发副本保持基线，不合并、不部署、不发布。

## 要验证的假设

把真正重复的确定性规则提到一个维护来源，再生成原部署目录所需的适配产物，能减少维护重复，同时保持现有协议、哈希、错误行为和恢复语义。此假设不同于“必须把全部状态统一进因果DAG”。

## 实验改动

建立 `packages/sync-contracts/src/contracts.mjs`，抽取身份／协议封装、公共metadata envelope、sourceScope以及已验证提交的固定字段序列化。Node端保留原生crypto和宿主canonical调用；PWA保留Web Crypto、Web Locks、storage和其原有验证边界。桌面专属backfill检查也保留在桌面适配器。

同名文件没有被机械合并。NativeTaskLinks持久投影、桌面／PWA任务投影、执行器、原生AA、HistoryMutationQueue、Ledger和权限存储都未改造。未引入新状态机、epoch、租约、数据库、DAG或新的副作用调度层。

生成器输出两个CJS产物和一个ESM产物，部署路径保留在overlays。`--check`从维护源码重新计算预期输出并逐字节比较；人为改错一个产物会失败，`--write`可从唯一来源恢复。生成产物仍有物理副本，但不再是三处手写逻辑。

## 证据

- 最终联合回归 **191/191通过**，22个文件，失败／取消／跳过均为0：原185项加6项契约场景。固定向量和等价性专项包含在这191项内，重叠运行不累计成新的用例数量。
- 对照旧实现时直接读取固定Git对象中的原始模块体，依赖重定向到原同伴模块和未改变的公开宿主能力，比较结果、错误code／status与哈希。不是把新函数复制一份当预期值。
- 固定向量锁定Unicode键排序、temperature的既有序列化、规范消息、metadata hash、scope hash和提交hash；另有256组合的Node／浏览器提交对照，包含组合字符、代理项和附件顺序。
- PWA在独立依赖副本中成功构建，生成8个产物；实际主JS从117588增至117812字节，增加224字节。没有运行手机或真实浏览器渲染验收，也没有据此宣称吞吐提升。
- 同一范围原手工模块489行，现有适配器233行＋共享契约149行＝382行；另加生成器25行，共407行。测试／文档及生成文件另计，总代码量并未被宣称下降。执行和恢复状态分支也没有“消失80%”。

来源摘要延续原provenance链，新增实验变更清单，不改写旧接受记录。全部夹具、输出和依赖副本位于实验worktree的Git忽略区；没有使用真实AppData或生产数据库。

## 结论与限制

**假设在本轮范围内成立：共享规则可以收拢，现有部署形态也可以保留。** 适配器不必承载重复的公共判断，但仍需拥有所在环境的I/O、认证和恢复职责。

代价也明确：增加生成步骤和产物完整性要求。协议／state格式不变，并不表示可以逐文件任意替换；这些适配器开始依赖新增的generated文件，若采纳，必须更新部署清单并验证安装依赖闭包。本文没有给出可直接执行的生产runbook。

本轮没有证明下列设想成立：统一所有业务事实存储、用事件广播替代耐久钩子、用epoch替代当前授权转换、用内存重放取代进程崩溃测试，或全面拆分headless runtime。上游canonical仍由各宿主提供，版本漂移需要既有指纹和冻结向量继续约束。

建议保留这个副本，先审阅抽取边界和构建代价；认可后只回收这块已证明等价的增量。后续再单独验证执行协调与同步账本的接口收敛，不能从本次通过跳到整套架构重写。
