没有增加宿主核心补丁。桌面分页复用已有 `getNativeExecutionStatus` preload 的第四个参数：原boolean含义保持，新分页对象 `{mode,limit,cursor}` 进入相同的只读IPC入口。新响应在IPC前做显式字段投影，不转发服务端未知字段。

手机任务分页不会代替原提交身份核对：精确查询仍受话题读取授权约束，可在会话轮换后返回原任务的公开证明；同requestId有多个候选时返回有界候选供恢复层拒绝歧义，不制造“未受理”的结论。其他会话的原提交正文不由该查询返回。

## 状态与协议兼容

Bridge state 采用 **version3 / native-message-intents-v2**。消息History、Journal、device／space／source、Outbox和已受理任务身份的含义保持。

- 旧v1先保留原备份与未证明删除的隔离，再迁入当前格式；旧v2按原字节语义保全备份，待处理事件落页后才切换状态。
- 正文页位于 `state.json.inbox/`，按内容摘要命名；主state保存事件身份、摘要、页引用、必要因果信息及恢复位置。读取验证路径、摘要和引用，正文缓存只保留一页。
- 正文落盘失败不推进游标；状态替换前／后退出均按最后已证明状态恢复；确认后才回收不再引用的页。损坏或缺失页会明确拒绝恢复，不用空队列替代。
- 旧版明确拒读v3。**采用新格式后不能恢复旧state、旧库或盲目换回旧客户端。** 备份用于取证和受控恢复，不是常规数据回滚。故障时保留当前状态，使用支持v3的候选向前恢复。
- 任务查询v2页量服务端上限128，游标绑定话题、模式和任务顺序上界；各页是当时状态观测，不宣称跨页原子快照。旧接口在原支持规模内兼容，过量时明确返回 `EXECUTION_PAGINATION_REQUIRED`。

合成账本存储微测：1千／1万条ack记录各跑5次空同步，主状态写入均为0；各跑5次真实变化事务仍为5次耐久提交，序列化合计约1.25MB／12.64MB。后者合计耗时约27ms／210ms，仅反映本机人工账本的存储开销，不是实际聊天吞吐指标。

本轮保留原CRLF产品字节约定（仓库 `* -text`），whitespace核对按 `cr-at-eol` 识别行尾，不为消除检查噪音全文件换行。来源摘要、敏感／禁止文件检查与JS语法核对按最终文件执行。
