## 实现范围

只修改PWA的App.vue与历史读取辅助层，新增historyCache.js。没有修改服务器、同步协议、数据库、任务、提交恢复存储或模型/工具/AA机制。

离开话题时，将已完成基线的消息Map及最后通过校验的游标暂存于当前页面内存。最多保留3个后台话题，字符串和容器估算预算32 MiB，按最近使用淘汰。超过预算的话题不缓存，之后仍走完整基线。当前正在显示的历史沿原逻辑存在，不计入这份后台缓存预算；预算不是进程RSS上限，也不宣称总内存恒定。

切回命中话题时：

1. 核对当前HttpOnly Cookie对应的服务器会话标记与后端入口身份。
2. 查询目录版本；版本改变才重新取分页目录，核对来源、owner、topic与授权范围。目录删除、身份改变、未完成接入的话题不复用缓存。
3. 使用原游标调用现有授权events接口，只接收增量。完整验证一页的归属、身份、序列和动作后才修改Map及游标；编辑、删除、追加沿原seq顺序应用。
4. 追赶完成后才显示缓存内容并开放新提交。执行任务、待确认提交及附件状态仍走原来的查询核对，不从历史缓存推断执行成功或触发重发。

会话标记变化时清除缓存并要求刷新核对；撤权、存储损坏或无效增量页拒绝继续显示缓存。网络暂时失败时保留待核对状态，不能离线切回缓存作为已授权历史。缓存不写localStorage、IndexedDB或Service Worker；原有待确认提交存储保持。退出、换会话及pagehide清理后台缓存。

刷新/新开页面、未完整加载过、旧历史协议或缓存被淘汰时仍需完整加载。缓存命中也仍有会话、目录及增量小请求，不能承诺零请求或瞬间切换。长时间离开且其他话题有大量新增时，现有全局游标仍可能需要多页扫描；本轮不重做拉取协议。大消息自身有更新时，增量也需要传输该消息的新版本。
